# Правила работы с документацией

- В основном тексте название продукта писать только в кавычках-ёлочках: `«QS: Спецодежда»`.
- На титульной странице книги название продукта писать без кавычек: `QS: Спецодежда`.
- Документация построена на Antora. Отдельные книги оформлять как отдельные модули, а их навигацию регистрировать в `antora.yml`.
- Между разными страницами использовать Antora-ссылки `xref:page.adoc#anchor[]`; конструкцию `<<page.adoc#anchor>>` оставлять только для ссылок на якорь внутри текущей страницы.
- PDF-книги собирать скриптом `build-pdf.sh` через Antora Assembler. Межкнижные ссылки в PDF должны вести на соседние `user-guide.pdf`, `admin-guide.pdf` или `practical-guide.pdf`, сохраняя обычный `xref` для онлайн-документации.

## Практическое руководство

- Материалы в `modules/practical-guide` писать как практическую книгу, а не как справочную или канцелярскую документацию.
- Вести читателя по ходу работы: «начнем с…», «сначала создадим…», «затем перейдем…», «после этого…».
- Предпочитать повествовательные фразы и активный залог. Допустимо обращаться к совместному действию через «мы» и формы первого лица множественного числа.
- Не использовать служебные формулировки наподобие «в этом разделе описано», «далее будет рассмотрено» и «выполняется настройка», если ту же мысль можно выразить как последовательность практических действий.
- Не повторять на дочерней странице обзор и выбор сценария, уже изложенные на родительской странице. Сразу продолжать повествование с первого практического шага.
- Страницы внутри `modules/practical-guide/pages` хранить на одном уровне, без тематических подпапок, если пользователь явно не попросил изменить структуру.
